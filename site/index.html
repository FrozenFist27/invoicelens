The problem

Retyping is slow. Guessing is worse.

Accounts-payable documents arrive in four different formats — and generic AI extraction fails in the one way that hurts most: silently.

  • !
    AP teams retype by hand. Supplier invoices and POs arrive as text PDFs, phone-camera scans, spreadsheets and email bodies. Each format means a different manual path into the ERP or spreadsheet.
  • !
    AI extraction looks right but fails silently. A wrong total or a swapped date goes straight into the ledger with no error, no warning, and no way to check it later.
  • !
    Nobody can say how accurate it is — so nobody trusts it. Happy-path demos prove nothing. Without per-field precision/recall on held-out documents, automation never gets signed off.

How it works

Route, read, extract, check, route again.

Five steps per document. Deterministic checks sit around the model, so nothing uncertain is ever silently accepted.

1

Ingest

Drop a file or forward an email; the document type is detected automatically (text PDF, scanned PDF, spreadsheet, email).

2

Read

Text PDFs are parsed directly, scans are OCR'd locally, spreadsheets are read cell by cell — every line carries a page or cell marker.

3

Extract

An LLM fills a fixed schema (supplier, numbers, dates, currency, line items, totals) and must cite the page and a verbatim snippet for each value.

4

Check

Line items must sum to totals, dates must be real and ordered, currencies must be valid ISO codes. Failures trigger a targeted correction retry (max 2).

5

Route

Confident fields go to JSON/CSV with source links. Uncertain ones go to a review queue — never a silent guess.

+

Measure

Every run logs tokens, cost and time per document. An evaluation harness reports per-field precision/recall on held-out documents.

Features

Built to be trusted, not just demoed.

Four inputs, one schema

Text PDFs, scanned PDFs, spreadsheets and emails all land in the same fixed output schema.

Per-field confidence

Each value carries a score combining model confidence, source grounding and rule checks.

Source traceability

Every field links to its page or cell with a verbatim snippet — an auditor can click back to the source.

Arithmetic validation

Line items must multiply out and sum to the totals; dates, currencies and required fields are checked too.

Targeted retries

When checks fail, only the failing fields go back to the model with the relevant page text — max 2 retries.

Review queue, not guesses

Low-confidence or still-invalid fields are held for a human, with the suggested value and the source snippet.

Cost & time reported

Tokens, dollar cost and stage timings are logged per document, so you can budget before you automate.

Tested pipeline

Validation rules, retry logic, routing and output formats are covered by a pytest suite that runs offline.

FAQ

Straight answers.

Does it work on my documents?

The public demo runs on synthetic data. For a client build, accuracy is measured on your own sample documents before you commit to automation — that measurement is part of every tier.

What happens when it is unsure?

The field goes to a review queue with the suggested value, the confidence score, the validation issues and the source snippet. It is never silently guessed, and the original value is never overwritten by the model.

Which AI model does it use?

Claude Haiku by default, called through a provider abstraction — so Gemini, OpenAI or a self-hosted model can be swapped in without touching the pipeline logic. Model id and prices live in a config file, not in code.

Is my data stored?

The demo deletes uploads after processing and keeps only aggregate counters. Client builds run inside your own environment, on infrastructure you control.

Can it read handwriting?

No. The OCR path uses Tesseract, which handles printed scans. Handwriting is out of scope for this demo and would be scoped separately if you need it.

How much does it cost to run?

The measured cost per document will appear in the Results section above after the evaluation run. You pay your own LLM usage; OCR and validation are local and free. Every run logs its own token usage and dollar cost.

Can it post to my ERP or accounting tool?

Not in this demo — the output is JSON and CSV with source links. Integrations (e.g. into QuickBooks, Xero, NetSuite or an internal API) are available as an add-on in a client build.
